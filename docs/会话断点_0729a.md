**现象**:`tools/ab_scripting/runtest_result.txt`(mtime **2026-07-27 21:44:26**,未归档)内容为
```
PRG_Test.iPassed = INT#76
PRG_Test.iFailed = INT#0

```
**算术矛盾**:ST 汇总循环是 `FOR i := 1 TO N_CASES`(`plc/06_PRG_Test.st` 尾部),每轮必给 passed 或 failed 加一,
两者之和**必然等于 N_CASES=77**。`76+0=76` 在数学上排除了「某项失败」,只能是**那次在线跑的应用里 N_CASES 不是 77**。

**根因**:
- `tools/ab_scripting/run_test.py:38` 用 `onapp.login(OnlineChangeOption.Try, True)` —— **在线更改**登录,非全量下载
- `N_CASES : INT := 77` 是 `VAR CONSTANT`,`plc/06_PRG_Test.st:12` 注释自己写着「常量化=N4-08,**在线不可改**」
- 两次 runtest 日志逐行 diff 后**只差 iPassed 那一行**,其余完全相同
- 0716 那轮正好是 **76**(`logs/runtest_result_20260716_135644.txt` → `iPassed=INT#76`)
→ 7/27 连上的是 0716 遗留的旧应用,在线更改改不动常量

**7/27 那次 sync 本身是成功的**:`sync_result.txt` 显示 `SYNCED: PRG_Test (pou, decl 1633 ch, impl 46765 ch)`、
`synced=48 fail=0`、`Compile complete -- 0 errors, 1 warnings` —— 即**源码同步与编译都对,只是没下载到仿真 PLC**。

**结论**:77/0 在**源码层**(`06_PRG_Test.st:12` N_CASES:=77)与 **0717 实测层**
(`logs/{sync,runtest}_result_20260717_010514.txt`:`Compile 0 errors` + `iPassed=INT#77 / iFailed=0 / xAllPass=TRUE`)**仍然成立**。
但存在真实风险:**默认 ab_sync 路径不做全量下载,改了常量后再跑会读回过时数字**。评委自行复现或我们再跑,很可能又拿到 76。

### 4.4-R 【推翻 §4.4】那天根本没跑过 AB;76 是 `git reset --hard` 还原出来的文件

0729 下午执行「写文档」这件拍板时,按纪律重新核实每条证据,查出 §4.4 的**事实叙述错了**。
§4.4 假定 7/27 发生过一次真实 AB 场次(「7/27 那次 sync 本身是成功的」「连上的是 0716 遗留的旧应用」),
**这个前提不成立**。四条独立证据:

1. `tools/ab_scripting/runtest_result.txt` 与 `logs/runtest_result_20260716_135644.txt`
   **逐字节完全相同**(连 ScriptEngine 的 `dir()` 列表和 `guid=74993588-6e2e-4450-94f1-a27f72e3ded1` 都一样);
   同批 `sync_result.txt` 与 `logs/sync_result_20260716_135644.txt` **也逐字节相同**
   —— 即 §4.4 里引的 `synced=48 fail=0`、`Compile 0 errors`、`SAVE_OK` **全是 0716 那轮的文本**,不是 7/27 的。
2. 两个文件的 mtime **相同到纳秒**:`2026-07-27 21:44:26.018723200`。
   而 `ab_sync.ps1` 分两阶段写它们、中间隔着编译 —— 0716 那对归档是 13:54 与 13:56,**差两分钟**。
   同纳秒只可能来自一次复制/还原。
3. `git reflog` 有 `c9a3363 HEAD@{2026-07-27 21:44:26 -0500}: reset: moving to HEAD` ——
   **时间戳精确吻合**;同一刻被改写的还有 `l4_showcase/app_shell/package.json` 与 `package-lock.json`
   (对应 `5f4d374` 21:49:46「修复并加固 QA 环境:codex 清空共享 pnpm 缓存…」那次抢修)。
4. `logs/` 里没有任何 0727 归档,而 `ab_sync.ps1` 第 43-52 行的归档是**无条件**的。

**修正后的结论**:
- 那个 76 **不是一次读回**,是 `git reset --hard` 把 0716 提交的文件还原回磁盘。**7/27 没跑过 AB。**
- **最后一次真实 AB 场次仍是 0717**(`logs/*_20260717_010514`,77/0),此后至今(0729)未再跑过。

  它是「能发生」,不是「已发生」。对外措辞不得写成已发生。
