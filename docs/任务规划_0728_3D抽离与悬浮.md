**先勘察后设计,三条实测事实定的方向**(非推测):
1. 两页曾有的「双轴速度」面板 `#liveChartWrap` 自一屏返工起就被 CSS 隐藏(`01_连续填仓.html:1104` 的 `html[data-s3-layout="A"] #liveChartWrap{display:none}`、`02_入出闭环.html:582` 无条件 `display:none`),其 `#speed` 画布实测矩形 **0×0**,而 `drawSpeed()` 每帧照画——纯空转的死代码。

**新建 `l4_showcase/src/s3_speed_profile.js`**(两页共用):示波器式**双泳道**速度-时间剖面。
- 为什么分泳道:VX=2.0 而 VZ=0.5(载货还 ×0.8),量级差 4~5 倍,共用一根绝对速度纵轴会把升降轴压成贴底直线——而实测多数货位行程**恰由升降轴主导**(等时区现象),主导轴的梯形反倒看不见,图就白画了。分泳道后两轴形态都可读,时间轴仍对齐,「谁先到位」照样一眼可见。
- 曲线一律由 `S3Motion` 采样,本文件**不含任何独立运动学实现**,避免出现第二套口径。
- 不重复显示实时速度数字(主位在轴状态行),只画形态与常量参数——遵守「同一数字只许一个主位」。
- 落点是**三维视口内浮层**而非底部 dock:实测 dock 高 110px、`#axisHud` 已占 74px,余 36px 放不下读得出梯形的图;且剖面图与场景分段路径本就要互相印证,同框才有意义。01 挂右上、02 挂左上——两页都是「三维区的外侧上角」(01 信息栏在左三维贴右,02 信息栏在右三维贴左),同一条视觉规则。

**场景内分段路径**(`s3_scene_core.js` 的 `addPath` 新增 `kinematicBreaks`):加速/匀速/减速三段用**同色相 + 不同粗细与浓度**(半径 ×0.58 / ×1.30 / ×0.58),不引入第三种颜色——路径色本身已编码操作类型(入库橙/空载蓝),再叠色相会与操作语义打架;粗细差异在灰度与色觉异常下同样可读。匀速段起止各放一枚刻度环。新增 `setAppearance()` 统一外观入口:分段后各段有各自材质,两页原先直写 `path.material.opacity/.color` 只会改到匀速段。

**退化保护(如实,不硬凑)**:主导轴为三角形速度剖面(行程短到加不满额定速度)或匀速档(02 档1 `constant_speed`)时,回落单段并在剖面图上如实画成三角形/平台。02 的 `LINK_TRAVEL` 已被 `dashPolyline` 拆虚线编码「空驶」,不再叠分段——语义带宽已满,且拆段后点列不再是等 progress 采样、时间参数已失真。
